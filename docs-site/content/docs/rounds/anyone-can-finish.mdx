Only the entry needs a signature (yours). Lock, settle and pay are spent by the contracts' rules alone, and the contracts pin every detail of them:

| Pinned | So that |
|---|---|
| Exact inputs and outputs, in a fixed order | No one can add, drop or swap a coin |
| Fixed fees, not fee rates | Every client computes the same amounts |
| Version 2, locktime 0, final sequence | No second variant of the same step can exist |
| The oracle message pair, chosen by sequence | Every client proves the same prices |
| Tickets paid in ascending outpoint order, up to 200 per batch | Every client batches the same way |

So the lock (or settle, or payout) our keeper builds is byte for byte the one your browser builds. The contract test suite proves it: two clients that list gates and tickets in opposite orders produce identical lock, settle and sweep transactions. When two parties send the same step, the second sees "already" and moves on.

## The buttons

A round page offers the step that's due when nobody has sent it:

| Round state | Button |
|---|---|
| Open, and past its start | **Lock this round** |
| Locked, and past its close | **Settle this round** |
| Settled or refunded, tickets unpaid | **Pay the tickets** |

The browser reads the round's coins from public Fulcrum servers and the signed prices straight from General Protocols (its API is open to any page), builds the step with the same code as the keeper, and broadcasts it. "Building from the chain…" while it works. No wallet, no signature, no fee from you: the round's own budget pays.

## If the oracle stops

If General Protocols never signs past a round's start or close, anyone can void the round 6 hours after its close and refund every ticket. That transaction is only valid after the deadline, and the node enforces it.
