Both languages were built and measured side by side first: each passed a full chipnet round, the attack suite and wallet signing. The split puts every contract a wallet signs against in CashScript, and gives SolidCash the contracts that are signed by a server key or by nobody, where its WizardConnect signing helper never comes into play. Every transaction is assembled with CashScript's builder; SolidCash contracts join through a small adapter.

| Contract | Language | Size | Functions | Its job |
|---|---|---|---|---|
| `LaneThread` | SolidCash | 575 B | `open` | Opens a lane's next round on its time grid, with a signed price as the clock |
| `Factory` | SolidCash | 1,084 B | `create` | Validated custom rounds and events (3 minutes to 30 days, up to 6 price ranges, fee ≤ 3%) |
| `Gate` | CashScript | 353 B | `enter`, `merge` | Takes entries, mints tickets, joins the lock |
| `EventGate` | CashScript | 644 B | `enter`, `merge`, `exit` | An event's gate: leave before the lock for a 3% fee that stays with the winners |
| `Ticket` | CashScript | 78 B | `spend` | Moves only with its own decided master (payout) or its own gate (exit) |
| `MasterOpen` | CashScript | 808 B | `lock`, `lockGold`, `lockTimeout` | Closes the gates at the oracle's first message past the start |
| `MasterLocked` | CashScript | 878 B | `settle`, `settleGold`, `timeoutVoid` | Proves the line and the close, decides, takes fees |
| `MasterSweep` | CashScript | 409 B | `sweep` | Pays tickets in batches, then returns the rest to the opener |
| `AgentVault` | SolidCash | 134 B | `bet`, `withdraw` | An agent's money: bets only into rounds, only for its owner ([Vault](/docs/agents/vault)) |

Five more CashScript contracts carry dollar-staked events in ParyonUSD (`DollarGate`, the three dollar masters, and `TokenSide`, which keeps each gate's tokens beside it).

## Commitments

Every token's state is its NFT commitment, little-endian, first byte a tag:

| NFT | Tag | Layout | Size |
|---|---|---|---|
| Lane thread | `0x05` | thread · asset · lane seconds · next start · counter | 12 B |
| Factory thread | `0x04` | thread · counter | 5 B |
| Master (open) | `0x01` | round id · state · asset · mode · gates · start · close · fee · opener · minimums | 46 B |
| Master (locked) | `0x01` | … · lock sequence · pot · entrants · totals | 61 B |
| Master (decided) | `0x01` | round id · state · winner · net pot · winning total · tickets left · opener | 42 B |
| Gate | `0x02` | round id · gate · class and outcomes · entrants · total per outcome | 20 B (40 B with 6 outcomes) |
| Ticket | `0x03` | round id · gate · outcome · stake · payout address | 32 B |

Gates and tickets stay at or under 40 bytes because Selene refuses to sign a transaction that spends an NFT with a longer commitment. Round ids are the thread byte plus a counter, so every lane numbers its own rounds.

## Sizes on chain

Measured on the test VM with today's contracts:

| Transaction | Bytes | Fee |
|---|---|---|
| Enter | 1,042 | 1,042 sats |
| Lock (2 gates) | 2,502 | 3,000 sats |
| Settle | 1,601 | 2,200 sats |
| Pay 3 tickets | 968 | 1,750 sats |
| Pay 200 tickets | 22,048 | 51,000 sats, 63% of the compute budget |

Tickets are bare-script (P2S) outputs, which halves the size of a payout: 200 tickets would take 44,571 bytes as P2SH32. A sweep carries 32 bytes of padding per ticket to buy the compute each payout check needs.
